# Gemma 4 Research Atlas

Snapshot: 11 November 2026. [Open the app](https://digiinformed-afk.github.io/gemma-4-competitions/atlas.html).

A self-contained, dependency-free interactive reference covering both competitions and the retrievable project record. Source: `web/atlas.html`, copied by the existing Pages build.

## Included
- Competition format, scoring, deadlines in Pakistan time, deliverables, model rules and award breakdown.
- Four permitted models, current 31B candidate, agent workflow and illustrative 12-hour budget calculator.
- Paper protocol, results, limitations and interactive candidate-elimination example.
- Saved three-arm pilot, V11 changes and newer V12/V14/memory/HTTPX reports with explicit evidence labels.
- Twelve public research/workflow entries, bottlenecks, decision gates and release checklist.
- Fifty-five technical concepts, learning marks, knowledge check, global search and source filters.
- Browser-local notes, progress backup import/export, downloadable self-contained app.

## Evidence boundary
The 7 November brief and 6 November research review were read. GitHub main, V11 README and prior-pilot-summary.json were inspected. Official sources and selected new primary research were checked.

The Control and Memory ZIP was identified but not extracted: its Library text read returned no readable content, and local execution was unavailable. Later V12/control/V14, memory diagnostic and HTTPX results come from recovered prior conversation reports. They are labelled **Reported**, never promoted to independently audited results.

No live Kaggle state, selected final submission, private leaderboard, newest-run checkpoint digest, trained adapter gain or broader Hikmah advantage is asserted. The original V11 files preserve their historical status.

Paper result: 85.48% finite held-out agreement is not real bug-fix success. The 18,000 rows are structured repeated conditions, not independent bugs. The 2/3 saved pilot and later HTTPX case are not merged into a matched 3/4 score.

## Personal state
Only notes, checklist, learned concepts and quiz answers use localStorage. JSON import accepts a bounded known schema and filters unknown IDs; rendered notes use text escaping. No secrets or restricted inputs are embedded. Source content does not auto-refresh. Browser progress does not sync with GitHub or submit to Kaggle.

## Validation
Automated checks are in `tests/atlas.test.mjs` and run through the existing `npm test` workflow. They exercise rendering all eleven pages in both depth modes, source integrity, budget overrun arithmetic, candidate elimination, search/filter coverage, import validation and delegated controls. The existing Pages workflow also runs the original project checks.

Local execution and the connected browser were unavailable during construction. CI is the execution environment; actual browser rendering remains an explicit verification limit.

## Source trail
Each factual topic links to an original source inside the app. The public field map combines a version-specific saved inspection with newer author-reported FGL and experiment-log evidence; it is selective and not a leaderboard.
